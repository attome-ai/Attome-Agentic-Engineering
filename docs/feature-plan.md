## A. Intent and requirements

From a sentence, a photo or an existing part to a checkable spec. Competitor scores come from the researched rows *Natural-language intent input* and *Requirements formalized and machine-checked*; detail rows say which row they carry. A3 is the category's limit: it reaches 80 by the demo, and A4 carries the native-CAD path after the competition.

### A1. Natural-language design brief
**Attome AE:** 95 · Designed
**Competitors:** Fusion 30 · nTop 0 · Siemens 30 · Creo 35† · Ansys 40 · SimScale 75 · Neural Concept 35† · PhysicsX 10 · Synera 50† · Zoo 80 · Adam 75 · PIL paper 70 · HEPH paper 75
**Plan:** The user describes a situation, not an engineering problem ("a wall shelf bracket that holds 100 kg, as light as possible, printed in PETG"), in English or Arabic, as text, a photo, a hand sketch or a dimensioned drawing. The agent (E1) turns it into an editable spec card (A2), asks only the questions that change the design (A5), and starts nothing until the user accepts the card.
- **Brief intake.** Dashboard chat and an MCP prompt for Claude Code/Desktop; both call the same `create_study` tool, so the behaviour is identical.
- **Use case to loads.** A load-derivation step turns situations into forces with the working shown: 100 kg → 981 N, times a stated factor (for example the EN 1990 partial factor 1.5 for variable actions), plus a drop or bump case when the brief implies handling. Every factor has a source in `structura/loads.py`; the LLM picks the case, it cannot invent a factor.
- **Images and drawings.** Claude vision reads a photo with a reference object, a sketch or a dimensioned drawing into dimensions with a confidence per value; low-confidence dimensions become questions (A5).
- **Arabic and English.** Briefs, questions, the spec card and the report work in both languages, with right-to-left layout in the dashboard.
- **Spec card.** Every extracted value is shown with where it came from (brief text, image, default, derivation); the user edits any value and sees the diff before the run.
- **Template match.** The agent picks a part family from the template library (B3) or flags "no template" and offers the gated fallback (B1).
- **Measured, not claimed.** A benchmark of 50 briefs (English and Arabic, text and image) with gold specs written by hand; the target is at least 90% of spec fields correct and 100% of units correct, reported per field in the proposal.
- **Why.** Every competitor that scores 60+ here (SimScale, Zoo, Adam, the papers) scores 0-20 on Pareto (D2), and none was found deriving loads from a use case or taking Arabic briefs.

**Today (score 45):**
- 50-brief benchmark scored: 95.0% of fields, 100% of units (`benchmarks/brief_bench_opus55_session.json`); run in a Claude Code session, not through the API, and with no image briefs. The harness's rules and gold disagree on unstated objectives (19 of 25 misses).
- The agent turns a brief into a spec through MCP tools (create_study, derive_load, rank_questions); no image or sketch input.

**How the leaders do it:**
- SimScale's Engineering AI agent goes from one prompt to a solved FEA/CFD/thermal study with an explanation; free on every plan, inside Onshape since Sept 2026.
- Zoo's Zookeeper writes parametric KCL code from text and self-checks with multi-view snapshots.
- Both May 2026 papers take an engineering brief in natural language and drive CadQuery → gmsh → FEA; their briefs state forces directly rather than situations.

### A2. Typed, machine-checked design spec
**Attome AE:** 95 · Designed
**Competitors:** Fusion 50† · nTop 40† · Siemens 55† · Creo 45† · Ansys 50 · SimScale 60 · Neural Concept 30† · PhysicsX 30† · Synera 55 · Zoo 20 · Adam 25† · PIL paper 65 · HEPH paper 80
**Plan:** Every study runs from a versioned `DesignSpec` with several load cases, worst-case evaluation, a feasibility check before any optimization, and a trace from every requirement to its check, its evidence and its report line.
- **Schema.** `structura/spec.py` (Pydantic) with mm-N-MPa-tonne units stored in the spec; a validator rejects missing units, unknown materials and bounds outside the template's.
- **Several load cases.** Each spec holds named cases (static service load, drop or bump equivalent, thermal when C2 applies); a design passes only when it passes every case, and the trust panel (F1) shows the governing case.
- **Worst case, not nominal.** Load ranges and a material knock-down for printed parts (strength reduced for the weak print direction, with the source of the factor) are evaluated at their worst combination.
- **Feasibility check first.** Beam-theory and mass bounds run in milliseconds before optimizing and flag impossible requirement sets with the reason and the nearest feasible limit ("under 40 g at safety factor 3 in PETG is not reachable; the estimated minimum is 55 g"). The user relaxes a limit or accepts the estimate.
- **Executable checkers.** Each limit becomes a function of the result schema giving pass/fail and margin, following Hephaestus-CCX's executable checkers.
- **Traceability.** Every requirement has an id that links brief sentence → spec field → checker → result evidence → report line; the report (I1) prints the table.
- **Versions and diffs.** Each spec edit creates a new version; any two runs show what changed in the spec and what it did to the result.
- **Materials.** A vetted table (PETG, PLA, Al 6061-T6, steel S235) with a source per value; the LLM cannot invent material properties.

**Today (score 75):**
- Typed spec with requirement ids and sources, load factors evaluated at the top of their range, print knock-down, feasibility by corner evaluation, versioning and an acceptance gate.
- Decision D9: unstated defaults are hard requirements only when they protect the user; conflicts are named when nothing is feasible.

**How the leaders do it:**
- HEPH (arXiv 2605.17448) ships 50 briefs with executable requirement checkers, one case per brief; the best formalization found.
- PIL (arXiv 2605.19717) targets a safety-factor band of 2-5 at minimum volume.
- SimScale writes objective, design space and assumptions into its PDF report.

**Plan:** The user uploads a STEP file and says what to improve ("same mounting holes, 30% lighter"). The part is solved as-is for the baseline, its interface features are detected and frozen, and it is redesigned either through the closest template or by shape operations inside its own envelope.

### A5. Questions that change the design
**Attome AE:** 95 · Designed
**Competitors:** Fusion 30 · nTop 0 · Siemens 30 · Creo 35† · Ansys 40 · SimScale 75 · Neural Concept 35† · PhysicsX 10 · Synera 50† · Zoo 80 · Adam 75 · PIL paper 70 · HEPH paper 75
**Plan:** Before asking anything, the agent runs a quick sensitivity sweep over every unknown in the spec (load direction, magnitude range, material, mounting, print direction) on a coarse mesh or the feasibility bounds (A2), ranks the unknowns by how much they move the design, asks only those above a threshold (at most three, ordered by impact), and defaults the rest with the default shown on the spec card.

- **Learn the threshold.** Answers and outcomes are logged so the threshold can be tuned on the A1 benchmark.
- **Why.** No competitor or paper was found choosing clarifying questions by their effect on the design.

**Today (score 40):**

**How the leaders do it:**

## B. Geometry generation

How shapes are made. The LLM never writes raw CAD code on the main path: it composes a typed **design graph** from vetted, parameterized features, and a compiler turns the graph into CadQuery. Every feature exposes its parameters and bounds, so every generated design can be optimized. Topology concepts come after the competition and are turned back into design graphs.

### B1. Text-to-CAD from scratch
**Attome AE:** 90 · Designed
**Competitors:** Fusion 15 · nTop 0 · Siemens 10 · Creo 20† · Ansys 10† · SimScale 5 · Neural Concept 35† · PhysicsX 5 · Synera 40† · Zoo 75 · Adam 60 · PIL paper 65 · HEPH paper 65
**Plan:** From the spec (A2) the agent composes a design graph (B3) out of grammar features, not CadQuery code. Several candidate graphs are generated, compiled, gated and reviewed by vision; survivors go to the optimizer. Free-form CadQuery remains only as a last resort for shapes the grammar cannot express, behind the same gate.
- **Compose, don't code.** The agent's tool takes a graph (JSON): features, their parent faces and parameter values; the compiler checks types and bounds before any geometry is built, so syntax and API errors cannot happen.
- **Best of N.** Five candidate graphs per brief; each must compile, pass the gate (B4) and pass a six-view render review against the brief; the rest are discarded with reasons logged.
- **Retrieval.** Verified graphs from earlier studies and the saved part families are retrieved by similarity to the brief and offered as starting points.
- **Repair.** Failures return a structured error to the agent inside the repair budget (E3).
- **Measured on a public benchmark.** Run Text2CAD-Bench (L1-L4) through the grammar path and report invalid rate, Chamfer distance and IoU against the published model results (GPT-5.2: 11.1% invalid on L1; about 70-90% invalid on L3 for most models). The score rises above 90 only if the benchmark shows we lead.
- **Why.** Free-form CAD code is the weak point of every text-to-CAD system measured so far; a typed grammar removes the failure class instead of repairing it.

**Today (score 60):**
- The agent composes design graphs (typed grammar), ranks several candidates (compose_candidates) and reviews six rendered views (render_views).
- Free-form CadQuery as a gated last resort (freeform_cad). Text2CAD-Bench not run.

**How the leaders do it:**
- Zoo leads text-to-CAD on its own B-rep kernel with KCL code and snapshot self-checks; fails on complex parts.
- Adam generates and edits feature-tree CAD; open-source CADAM writes OpenSCAD.
- Text2CAD-Bench (May 2026): GPT-5.2 11.1% invalid on simple shapes, roughly 70-90% invalid on sweeps, lofts and shells for most models.

### B4. Geometry validity gate and auto-repair
**Attome AE:** 95 · Designed
**Competitors:** Fusion 55† · nTop 45 · Siemens 70 · Creo 50† · Ansys 80 · SimScale 65 · Neural Concept 30† · PhysicsX 30 · Synera 55 · Zoo 30 · Adam 25 · PIL paper 70 · HEPH paper 70
**Plan:** Before meshing, every candidate passes the gate, and the gate repairs what it safely can. The measured goal is that at least 99% of gated designs mesh, against 76-88% meshing after 96-97.5% code execution in PIL.
- **Checks.** Valid B-rep, exactly one solid, volume > 0, inside the design space, outside keep-out zones, minimum wall thickness, minimum feature size against the target mesh size, printability (overhang angle for the print direction, minimum hole diameter).
- **Repair.** Remove fillets and faces smaller than the minimum feature size, merge sliver faces (OCCT ShapeUpgrade), heal small gaps; every repair is logged and the repaired shape is gated again.
- **Mesh-ability prediction.** A classifier on cheap geometric features (smallest face area, face count, minimum edge length, thickness ratio) trained on the P1 sweep predicts mesh failure; predicted failures are coarsened or repaired before gmsh runs.
- **Measured.** Gate-pass → mesh-success rate over the P1 and P2 sweeps, reported in docs/benchmarks.md.

**Today (score 80):**
- Geometry gate (validity, single solid, design space, keep-out, preserve, minimum wall, edge and hole, overhang) with safe repair: 499 of 500 random designs pass, all gated designs mesh.

**How the leaders do it:**
- Scores carried over from the researched row *Verification and trust reporting*; this detail row was not researched on its own, so treat every score as low confidence.

## C. Simulation physics

Real solvers, never surrogates alone. Each feature says what is built **before 3 February** and what comes **after**. The ceiling here is about 86: Ansys (FEA 95, CFD 95, thermal 90) and Siemens have decades of solver breadth, so physics is planned to be credible and verified, not to beat them. Setup and meshing (C3, C4) are where Attome AE can lead.

### C1. Structural FEA: static, modal, buckling, nonlinear
**Attome AE:** 90 · Designed
**Competitors:** Fusion 75† · nTop 65 · Siemens 90 · Creo 75† · Ansys 95 · SimScale 75 · Neural Concept 50† · PhysicsX 55† · Synera 60 · Zoo 0 · Adam 30† · PIL paper 60 · HEPH paper 70
**Plan:** CalculiX (ccx 2.22/2.23, conda-forge on Windows) as a subprocess on quadratic C3D10 tetrahedra, with the deck written directly from gmsh arrays and results parsed into the result schema. Every analysis type below is a CalculiX capability the engine wraps; none is a new solver.
- **Before 3 Feb: linear static.** Von Mises, principal stress, displacement, reactions, mass; node order remapped from gmsh to CalculiX; agent-immutable settings.
- **Before 3 Feb: modal and buckling.** `*FREQUENCY` for the first natural frequencies (a minimum-frequency requirement in A2) and `*BUCKLE` for the buckling load factor of slender ribs, the failure HEPH reports most for slender members.
- **Before 3 Feb: refinement where it matters.** A recovered-stress error estimate per element drives local mesh refinement at concentrations until peak stress changes by less than 5% (F1 records the levels).
- **Before 3 Feb: realistic bolted supports.** Mounting holes are supported through `*COUPLING` with `*DISTRIBUTING` to a reference node per bolt instead of fixing the whole hole face, which avoids the false stress peaks of rigid fixing.
- **After 3 Feb: nonlinear.** Large deflection (`NLGEOM`), elastic-plastic materials and contact between parts for assemblies (Level 2 of the ladder).
- **Validation.** Cantilever, NAFEMS LE10 and a modal case against the analytical beam frequency, all in F2.
- **Why not 95.** Ansys adds explicit dynamics, fatigue, composites and decades of verification; 90 is the credible ceiling for a wrapped open solver.

**Today (score 78):**
- Bolted supports tie each bore's mean translation to a held reference node; adaptive refinement matches Peterson's Kt within 0.24%. On the bracket, bolted bores change deflection by 0.07% and peak stress not at all.
- CalculiX static stress, frequency and buckling, all validated (LE10 +0.14%, LE1 -0.40%, cantilever -0.80%, buckling +0.06%, frequency -0.26%); frequency and buckling requirements work in specs.
- No nonlinear material or contact.

**How the leaders do it:**
- Ansys and Siemens lead with reference-grade solvers.
- SimScale runs cloud FEA from a prompt.
- HEPH uses exactly CadQuery → gmsh → CalculiX, static only.

### C2. Thermal: steady, transient and thermal stress
**Attome AE:** 85 · Designed
**Competitors:** Fusion 60† · nTop 50† · Siemens 85 · Creo 65 · Ansys 90 · SimScale 75 · Neural Concept 50† · PhysicsX 50† · Synera 50† · Zoo 0 · Adam 15† · PIL paper 0 · HEPH paper 0
**Plan:** CalculiX heat transfer (DC3D10) on the same parametric model as C1, so a heat sink and a bracket share one pipeline.

**How the leaders do it:**

### C3. Loads and supports from the spec
**Attome AE:** 95 · Designed
**Competitors:** Fusion 35 · nTop 5 · Siemens 25 · Creo 35† · Ansys 40 · SimScale 75 · Neural Concept 35† · PhysicsX 10 · Synera 75 · Zoo 65 · Adam 65 · PIL paper 75 · HEPH paper 80
**Plan:** Boundary conditions are never placed by the LLM choosing face indices. They come from named faces of the design graph (B3), from features detected on uploaded parts (A3), or from the user's click, and every set is checked before solving.
- **Before 3 Feb: named faces.** Grammar features name their faces (mount_holes, load_face, fin_faces), so "fixed at the wall holes, 981 N down at the tip" maps to groups directly.
- **Before 3 Feb: inferred supports.** Detected hole patterns become bolted supports (C1), planar contact faces become compression-only supports; the inference is shown in the viewer for confirmation.
- **Before 3 Feb: click to select.** In the viewer the user clicks faces to add or change a load or support; the spec (A2) records the face ids and a geometric signature so they survive parameter changes.
- **Before 3 Feb: setup checks.** Before the solve: the structure is not free to move (rigid-body modes), not over-constrained against thermal expansion, loads land on existing faces, and after the solve reactions balance applied loads within 0.5%.
- **Why.** Wrong boundary conditions are the most common source of plausible but wrong FEA results; a setup that a non-expert can see and that checks itself is the gap the agent tools leave.

**Today (score 75):**
- Setup checks before any solve: supports must stop all six rigid-body motions, loads must act on real faces that are not fully held. No click-to-select or inferred supports.
- Loads and supports on named faces, factor ranges, load derivation from kg with sources, partial supports; loads and supports drawn in the viewer.

**How the leaders do it:**
- Scores carried over from the researched row *LLM agent drives the tools*; this detail row was not researched on its own, so treat every score as low confidence.
- SimScale's agent sets boundary conditions from the prompt on existing CAD.

### C4. Robust, adaptive meshing
**Attome AE:** 95 · Designed
**Competitors:** Fusion 55† · nTop 45 · Siemens 70 · Creo 50† · Ansys 80 · SimScale 65 · Neural Concept 30† · PhysicsX 30 · Synera 55 · Zoo 30 · Adam 25 · PIL paper 70 · HEPH paper 70
**Plan:** gmsh in a subprocess with a fixed fallback ladder, a mesh-ability predictor in front (B4), local sizing where the physics needs it, and refinement driven by the error estimate (C1). Target: at least 99% of gated designs mesh, measured on 500 designs.
- **Before 3 Feb: ladder.** HXT → Delaunay → Frontal, then size × 1.5, then fTetWild on an STL; every attempt logged.

## F. Verification and trust

### F1. Trust panel and verification report
**Attome AE:** 95 · Designed
**Competitors:** Fusion 55† · nTop 45 · Siemens 70 · Creo 50† · Ansys 80 · SimScale 65 · Neural Concept 30† · PhysicsX 30 · Synera 55 · Zoo 30 · Adam 25 · PIL paper 70 · HEPH paper 70
**Plan:** Beside every design: each requirement with pass/fail and margin, the numerical error of each reported value, independent sanity checks, the modelling assumptions, and a confidence grade with a written rule. Nothing is shown as verified unless its check ran, and the agent cannot write to the trust record.
- **Before 3 Feb: requirement margins.** Every requirement from the spec (A2) with value, limit, margin and governing load case.
- **Before 3 Feb: numerical error bars.** Peak stress, displacement, frequency and temperature are solved on three mesh levels; the Grid Convergence Index gives an error estimate per value, and a requirement whose margin is smaller than its error is shown as "not proven", not as pass.
- **Before 3 Feb: independent sanity checks.** Reaction forces balance applied loads within 0.5%; strain energy equals the work of applied loads; a hand calculation (beam theory for the governing section) agrees with FEA within a stated factor, and a disagreement is flagged for review.
- **Before 3 Feb: assumptions in plain words.** Linear elastic, small deflection, the material values and their sources, the print knock-down, the convection correlation and its validity range.
- **Before 3 Feb: confidence grade.** A, B or C from a published rule: A needs every check run and passed, GCI below 5% on governing values and a passing validation suite; B allows GCI up to 10%; anything else is C. The rule is on the panel.
- **Before 3 Feb: reproducible evidence.** Each design's evidence bundle (spec, graph, mesh, deck, results, solver version, environment hash) is content-hashed; one command re-runs it and must reproduce the reported numbers.
- **Before 3 Feb: physical evidence.** When the printed test (H3) exists for a design, measured against predicted stiffness is shown on the panel.
- **After 3 Feb: credibility assessment.** A per-study credibility table in the spirit of NASA-STD-7009 (verification, validation, input pedigree, uncertainty, use history), filled from the evidence the engine already records.
- **Why.** Public verification evidence is weak for almost every physics-AI vendor, and execution-based and field-level success can differ by about 20 points (arXiv 2609.03718).
